# eaiku v0.1 — Design Spec

- **Date:** 2026-09-28
- **Status:** Draft, waiting for review
- **Target release:** v0.1.0

## 1. Summary

eaiku ("AI-ku", "my AI" in Indonesian) is a local-first, forkable AI hub. Users clone the repo and run it on their own machine. The user's own local agent (Claude Code for now) does the AI work. eaiku does not host any LLM.

eaiku has a plugin system. The first plugin is **Catat** ("take notes"). Catat turns a YouTube video into a note that explains the content. It does not compress the content into a bland summary.

There are two entry points:

1. **Claude Code skill:** `/catat <youtube-url>` makes a note and saves it on the local disk.
2. **Web app (Next.js):** it reads the saved notes and shows them.

The note JSON schema is the contract between the two.

eaiku.com shows a read-only static demo with sample notes.

## 2. Goals and non-goals

### Goals for v0.1

- `/catat <youtube-url>` makes a valid note with verified timestamp citations.
- Videos longer than 10 minutes are split into parts. Each part becomes one note.
- The web app lists, searches, and shows notes.
- The plugin contract is real: Catat uses the same contract that future plugins use.
- A static read-only demo runs on eaiku.com.
- semantic-release manages the version.

### Non-goals for v0.1

- The web app does not call any LLM. (v0.2: "New note" button with the Claude Agent SDK.)
- No quiz. No flashcards. (v0.2: flashcards made from `concepts`.)
- No paste-by-hand transcript fallback. (v0.2.)
- No settings form on the Plugins page. (v0.2.)
- No languages other than English.
- No PDF or EPUB sources. (v0.3: PDF. Later: EPUB.)
- No runtime plugin install. Plugins load at build time.
- No login. No sync.
- No 3D orb. The landing page uses CSS 3D text. (The orb is a later change to one component.)
- No custom YouTube transcript library. We use the `youtube-transcript` npm package.

### 3.2 Division of work

- **The agent (Claude) does the thinking:** it reads the transcript, proposes cut points, and writes the note.
- **The CLI does the deterministic work:** it fetches the captions, snaps the cut points, validates the note, checks the citations, and writes the files and database rows.

The agent never calls YouTube directly. Every saved note passes the schema.

## 4. Note schema (the contract)

File: `plugins/catat/schema/note.ts`

```ts
import { z } from "zod";

export const SourceRef = z
  .discriminatedUnion("kind", [
    z.object({
      kind: z.literal("timestamp"),
      startSec: z.number().nonnegative(),
      endSec: z.number().optional(),
    }),
    z.object({ kind: z.literal("page"), page: z.number().int().positive() }),
    z.object({
      kind: z.literal("chapter"),
      chapter: z.string(),
      page: z.number().int().optional(),
    }),
  ])
  .and(
    z.object({
      quote: z.string().max(200).optional(), // exact words from the source; used for citation checks
    }),
  );

export const Source = z.discriminatedUnion("type", [
  z.object({
    type: z.literal("youtube"),
    url: z.string().url(),
    videoId: z.string(),
    title: z.string(),
    channel: z.string().optional(),
    durationSec: z.number(),
    captionLang: z.string(),
    range: z.object({ startSec: z.number(), endSec: z.number() }),
  }),
  z.object({ type: z.literal("pdf"), fileName: z.string(), title: z.string(), pageCount: z.number() }),
  z.object({ type: z.literal("epub"), fileName: z.string(), title: z.string(), author: z.string().optional() }),
]);

export const Section = z.object({
  id: z.string(),
  heading: z.string().max(80),
  body: z.string(), // Markdown, no raw HTML
  analogy: z.string().optional(),
  refs: z.array(SourceRef).min(1),
});

export const Concept = z.object({
  term: z.string(),
  definition: z.string().max(300),
  refs: z.array(SourceRef).min(1),
});

export const Note = z.object({
  schemaVersion: z.literal(1),
  id: z.string(), // slug, e.g. "2026-09-28-intro-to-llms-p2"
  createdAt: z.string().datetime(),
  style: z.enum(["friendly", "textbook"]),
  source: Source,
  series: z
    .object({
      id: z.string(), // same for every part of one video (the videoId)
      part: z.number().int().positive(),
      total: z.number().int().positive(),
      partTitle: z.string(),
    })
    .optional(), // absent when the whole video is one note
  title: z.string(),
  hook: z.string().max(280),
  keyTakeaway: z.string().max(280),
  sections: z.array(Section).min(3).max(8),
  concepts: z.array(Concept).min(3).max(12),
  openQuestions: z.array(z.object({ question: z.string(), why: z.string() })).max(5),
  tags: z.array(z.string()).max(8),
  generator: z.object({
    agent: z.literal("claude-code"),
    model: z.string().optional(),
    promptVersion: z.string(),
  }),
});

export type Note = z.infer<typeof Note>;
```

### 4.1 Schema rules

- Every section and every concept must cite the source (`refs.min(1)`).
- The hard limits (3–8 sections, 280-character hook) stop two failure modes: the transcript dump and the 3-sentence summary.
- `openQuestions` means "things the source mentions but does not explain". Each item needs a `why`. If this field gives noise in practice, we remove it.
- `note.json` never changes after save. App state (for example reading progress later) goes in SQLite.
- v0.1 makes only `youtube` sources and `timestamp` refs. The other variants exist so the contract does not change in v0.3.

## 5. Plugin contract

A plugin has four parts:

| Part | Job |
|---|---|
| Manifest | Tells eaiku what the plugin is and what it needs |
| CLI tools | Deterministic steps that the agent calls |
| Agent package | Claude Code plugin (skills, commands) that tells the agent how to do the job |
| UI | Pages in the web app |

### 5.1 Manifest

```ts
// packages/core/src/plugin.ts
export interface EaikuPlugin {
  id: string;                        // "catat": storage folder, table prefix, URL prefix
  name: string;
  description: string;
  version: string;                   // same as the repo version in v0.1
  icon: string;                      // lucide icon name
  healthChecks: HealthCheck[];
  launcherActions: LauncherAction[];
  pages: Record<string, PluginPage>; // mounted under /p/<id>/...
  db?: { schema: unknown; migrationsDir: string };
}

export type LauncherAction =
  | { label: string; kind: "route"; href: string }
  | { label: string; kind: "copyCommand"; command: string };

export interface HealthCheck {
  label: string;
  run: (ctx: PluginContext) => Promise<{ ok: boolean; hint?: string }>;
}

export interface PluginContext {
  home: string;       // EAIKU_HOME
  storage: Storage;   // readJson / writeJson / list, limited to <home>/<plugin-id>/
  db: Database;       // shared better-sqlite3 + Drizzle instance
}
```

Catat launcher actions: "New note" (`copyCommand`, `/catat `) and "My notes" (`route`, `/p/catat`).

Catat health checks: YouTube reachable, and database migrations applied.

### 5.2 CLI tools

- The CLI runs as `pnpm eaiku <plugin> <command>`.
- JSON goes to stdout. Errors go to stderr as JSON. Exit code 0 means success. Any other code means failure.
- Each command does one step.
- The CLI works with any agent. An MCP server can wrap it later without changes to it.

### 5.3 Agent package

- `plugins/<id>/claude/` uses the Claude Code plugin format.
- The root `.claude-plugin/marketplace.json` lists all plugins.
- Install: in the cloned repo, run `/plugin marketplace add ./`, then install `catat`.

### 5.4 UI and loading

- A build script scans `plugins/*/manifest.ts` and writes `apps/web/plugins.generated.ts`.
- One catch-all route, `app/p/[plugin]/[[...slug]]/page.tsx`, finds the page in the registry.
- Plugin pages are React Server Components.
- The enable/disable toggle writes to `config.json`. No rebuild is needed.

### 5.5 Trust model

Plugins are trusted code, as in Strapi. The storage and table-prefix limits are conventions, not a sandbox.

## 6. Storage

### 6.1 Layout

```
~/eaiku/                                   # or $EAIKU_HOME
├─ config.json                             # enabled plugins
├─ eaiku.db                                # SQLite, shared by all plugins
└─ catat/
   ├─ transcripts/<videoId>.txt            # captions for the agent, one line per sentence group
   ├─ transcripts/<videoId>.json           # metadata + raw segments, used by plan (snap) and save (citation checks)
   ├─ drafts/<draftId>.json                # agent drafts before save
   └─ notes/<noteId>/note.json             # the contract; never changes after save
```

### 6.2 Source of truth

- The JSON files are the source of truth.
- SQLite is the index and the app state.
- `eaiku catat save` writes the file and the rows in one step.
- `eaiku reindex` rebuilds the database from the files. The database is disposable.
- The web app reads from SQLite only.

### 6.3 SQLite

- Library: `better-sqlite3` + Drizzle ORM. `better-sqlite3` goes in Next.js `serverExternalPackages`.
- Each plugin prefixes its tables with its id.
- On start, core runs any plugin migrations that did not run yet. It records them in `_migrations`.

Catat tables:

| Table | Columns |
|---|---|
| `catat_notes` | id, title, video_id, channel, style, start_sec, end_sec, series_id, part, total, hook, key_takeaway, created_at, path |
| `catat_note_tags` | note_id, tag |
| `catat_notes_fts` (FTS5) | title, hook, key_takeaway, sections_text, concepts_text |

## 7. The `/catat` flow

Usage: `/catat <youtube-url> [--from mm:ss --to mm:ss] [--style friendly|textbook]`

Default style: `friendly`.

### Step 1: fetch

Claude runs `eaiku catat fetch <url>`. The command:

1. Reads the video ID from `watch?v=`, `youtu.be/`, `shorts/`, and URLs with `&t=`.
2. Gets the title and channel from the YouTube oEmbed endpoint.
3. Gets the captions with `youtube-transcript` and `lang: 'en'`. Offsets are in milliseconds, so it converts them to seconds.
4. Tries to get the chapters from the watch page. If this fails, it continues without chapters.
5. Uses the end of the last caption segment as the duration.
6. Joins caption fragments into sentence groups. It writes `transcripts/<videoId>.txt` with lines such as `[12:40] so the tokenizer splits the text...`.
7. Prints a small JSON summary: videoId, title, channel, durationSec, chapters, and the transcript path. It does not print the full transcript.

All calls to `youtube-transcript` go through one file: `plugins/catat/lib/fetch-transcript.ts`.

### Step 2: plan (only for videos longer than 10 minutes, with no `--from`/`--to`)

1. If the video has chapters, the chapters are the parts.
2. If not, Claude reads the transcript and proposes cut points at topic shifts. The target is about 10 minutes for each part (minimum 5, maximum 15).
3. `eaiku catat plan <videoId> --cuts 760,1445,...` moves each cut to the longest pause between caption segments within ±120 seconds.
4. Claude shows the plan and asks the user which parts to make (`all`, `1,2`, `1-3`). The skill suggests 3 parts or fewer for each run.

### Step 3: write

For each chosen part:

1. Claude reads only the transcript lines in the part's range.
2. Claude follows the writing guide in `SKILL.md`: explain, do not compress. Start with a hook. Use analogies. Cite timestamps with short exact quotes. Expect auto-captions with no punctuation.
3. Claude writes the draft to `catat/drafts/<draftId>.json`.

### Step 4: save

`eaiku catat save <draftPath>`:

1. Validates the draft with the Zod `Note` schema.
2. Checks the citations. Each timestamp must be inside `source.range`. Each `quote` must appear in the transcript within ±30 seconds of its `startSec`. The match ignores case and punctuation.
3. If a check fails, it prints a JSON list of errors and exits with code 1. Claude fixes the draft and runs `save` again. After 3 failed attempts, Claude stops and shows the errors to the user.
4. If all checks pass, it writes `notes/<noteId>/note.json`, upserts the SQLite rows, deletes the draft, and prints `http://localhost:3000/p/catat/<noteId>`.

### Errors in v0.1

Each error gives a clear message and stops the flow:

- The URL is not a YouTube video URL.
- The video has no captions.
- The video has no English captions. The message lists the available languages.
- There is no network, or YouTube blocks the request.

## 8. Web app

### 8.1 Pages

| Route | Content |
|---|---|
| `/` | Landing page. One screen, no scroll. Glass style. "EAIKU" as CSS 3D text in the middle. The text tilts a little with the mouse. On click, it zooms out and the launcher pills fade in. "Plugins" link at top right. Copyright line at the bottom. |
| `/plugins` | Installed plugins, health check results, and enable toggle |
| `/p/catat` | Notes list: FTS search, tag filter, and parts grouped by series |
| `/p/catat/<id>` | Note page: hook, key takeaway, sections with analogy callouts, concepts, open questions. Each timestamp chip opens YouTube at that second (`&t=<sec>s`). Series notes link to the previous and next parts. |

- The landing page uses no WebGL. The 3D text is one component, so a future orb can replace it and keep the same flow.
- The landing page respects `prefers-reduced-motion`: no tilt, and a simple fade on click.

### 8.2 Visual style

- The whole web app uses one visual style: friendly, modern, dark theme, and fun.
- Dark background, glass panels (blur and a thin light border), and one bright accent color.
- Friendly details: rounded corners, soft motion, and short, warm UI copy.
- Design tokens (colors, radius, spacing, fonts) live in one shared SCSS file.

### 8.3 Demo mode (eaiku.com)

- `EAIKU_HOME=apps/web/demo-data`.
- The build runs `eaiku reindex`, then `next build` with a static export.
- A static site has no server, so FTS cannot run. Demo search uses a client-side filter on a JSON index made at build time.
- The Plugins page shows a "demo mode" label, and the toggles are off.
- Demo notes use Creative Commons videos or the author's own videos. The demo does not ship transcript files.
- Hosting: Cloudflare Pages (the domain is already on Cloudflare).

## 10. Versioning and release

- semantic-release runs in GitHub Actions on each push to `main`.
- `feat:` → minor. `fix:` → patch. `BREAKING CHANGE` → major.
- It creates the git tag, the GitHub release, and `CHANGELOG.md`.
- The whole repo has one version. Plugins do not have their own versions in v0.1.
- semantic-release starts at 1.0.0 by default. To prevent this, we tag the first scaffold commit on `main` as `v0.0.0` by hand.
- All v0.1 work happens on the branch `feat/v0.1`. When we merge it to `main`, semantic-release sees `feat` commits after `v0.0.0` and releases `v0.1.0`.
- After that, semantic-release takes over for every push to `main`.

## 11. Testing

- **Unit tests (Vitest):**
  - URL parsing for all URL shapes.
  - Millisecond-to-second conversion and sentence grouping.
  - Snap logic: the cut moves to the longest pause within ±120 seconds.
  - Citation check: timestamp out of range, quote not found, quote found with different case and punctuation.
  - Schema: valid note passes; each hard limit fails.
  - `reindex` rebuilds the same rows as `save`.
- **Fixture tests:** saved caption fixtures for 3 videos, so tests do not call YouTube.
- **Manual check before v0.1.0:** run `/catat` on 3 real videos (short, medium, long with parts). All notes pass `save`.

## 14. Risks

| Risk | Mitigation |
|---|---|
| `youtube-transcript` breaks (for example PoToken changes) | One wrapper file. Requests come from the user's home IP, which YouTube blocks less often than cloud IPs. |
| Claude writes invalid JSON or wrong quotes | `save` validation and citation checks, 3 attempts at most |
| Long series fill Claude's context | The skill suggests 3 parts or fewer for each run |
| Static export cannot run SQLite FTS | Client-side filter on a JSON index in demo mode |
| `better-sqlite3` fails to install | README pins Node 22 and lists the fix |
| Copyright in the public demo | Creative Commons or own videos only. No transcript files in the demo. |
